# V13 test procedure

Build: `13.0.0-dev.6`. Evidence: locally validated, **not live verified**. Use a copied/backed-up world. Fill in actual Foundry build, D&D5e, Midi-QOL, Combat Carousel and ZFT Tools versions before acceptance. Do not infer V14 support.

Expected startup console: `[ZFT] Round Initiative v13.0.0-dev.6 | Ready.` Followed by the tracker access note. Action failures produce `[ZFT] ... | Action failed` plus a useful notification. JavaScript exceptions or unhandled promise errors are failures.

| Check | Action and expected result | Current live result |
| --- | --- | --- |
| Embedded layout | Docked and popped-out native trackers show one compact status strip directly under the round/settings header and outside the scrolling list, with Request, Begin & Protect, Restore, History and Details icons. No separate control window opens during normal workflow. Hover/focus all controls and the encounter/status text. | NOT TESTED |
| Compact strip | Check docked/popout trackers at normal and increased zoom, and narrow widths. Each action has a 24x24px CSS box; at ordinary widths the strip is about 32px high. No inherited tall button box. At very narrow widths status may wrap above the icon group. Tab to enabled/disabled controls; Enter/Space act only when enabled; tooltip reasons remain readable. | NOT TESTED |
| Compact row icons | Make Current uses an inline arrow/check with the same footprint as adjacent native icons. Measure its wrapper and icon; neither should exceed 20px high or increase a combatant row. Check hover/current/disabled states, keyboard, names/effects/badges and zoom with many combatants. | NOT TESTED |
| Inline edit | Active GM clicks or keyboard-activates a rolled number, enters 28.20, presses Enter: exact numeric value is saved and the current combatant remains selected through sorting. Zero/negative values work. There is no DEX recalculation. | NOT TESTED |
| Edit cancellation | Escape or clicking away cancels. Blank/invalid input saves nothing. A native redraw, closed tracker or replaced field never blur-saves pending text. Repeated Enter makes one write. | NOT TESTED |
| Edit safety | Change round, viewed encounter or that initiative from another window while editing. The stale save is refused. Two identically named NPCs and simultaneous dock/popout instances target stable IDs. Players and inactive GMs cannot mutate. | NOT TESTED |
| Edit/recovery | Before Begin, an edited value is captured as the start. After protection, another edit shows Changed; Restore recovers the original roll with the current combatant retained. Existing native/third-party inputs and unrolled die controls remain usable. | NOT TESTED |
| Movement history investigation | Owner deferred this test. With a measured move recorded, inspect public movementHistory counts before Request, after Request and after Begin, comparing the same token with manual Clear Movement History. Test a changing and unchanged first combatant, plus native turn/round controls. This build adds no explicit movement clearing. | DEFERRED BY OWNER |
| Tracker lifecycle | Open both native tracker forms, close/reopen popout, switch encounters and update initiative/names. Each gets one strip and one button per real combatant. No duplicate listeners; stale/closed-window controls cannot act. Existing focus remains during owned-state refreshes. | NOT TESTED |
| Timing coexistence | Test Turn Time on/off and both render-hook orders. Pause/reset/edit/report and timing labels stay usable and unchanged by injection. Native turn changes still notify timers. Narrow/zoomed trackers wrap without hiding controls or stretching a footer button. | NOT TESTED |
| Make current | In Round 4 click the arrow next to a different combatant, including two NPCs with the same name. Exactly that entry becomes current with the same round, initiative values and history. No canvas token selection or panning. Current entry has a disabled check icon; keyboard focus exposes its reason. | NOT TESTED |
| Make current safety | Resort initiative before clicking, remove an entry, switch viewed encounters, rapid double-click, and try as a player/inactive GM. No wrong combatant, invalid turn, unauthorized write or snapshot overwrite. Test native turn effects, logs, timing and Carousel for actual behavior. | NOT TESTED |
| Longer notice | Native Round 3 -> 4 says Round 3 Complete / Prepare for Round 4 for about 8 seconds by default. Change Automatic round notice duration; manual notice preference remains intact. Trigger Request during the banner: the Roll Initiative prompt replaces it immediately. | NOT TESTED |
| Automatic transition | Finish the last native turn in Round 1. Foundry shows Round 2; the module says Round 1 Complete / Prepare for Round 2. Initiative and selected combatant are not changed by the notice. Manually Request Initiative to show Round 2: Roll Initiative. | NOT TESTED |
| First start | Native 0 -> 1 says Prepare for Round 1, without Round 0 Complete. If initiative was already requested before starting, do not replace the roll prompt with a late preparation banner. | NOT TESTED |
| Notice deduplication | Use two GM clients and a player; one transition notice per client. Refresh/reconnect, rewind and return to a previously announced round, or manually jump round numbers: no fabricated/replayed completion notice. | NOT TESTED |
| Notice ordering | Request rolls immediately after native advancement. A delayed preparation announcement must not replace the newer Roll Initiative prompt. Change GM authority or delete the encounter during publication: no stale or unauthorized broadcast. | NOT TESTED |
| Layout persistence | Explicitly open Details, move that panel and change mode. Close/reopen and refresh: mode and position persist per client. Reopen on a smaller viewport: panel stays on screen. | NOT TESTED |
| Encounter naming | Save a name in Combat Log's initial prompt while Round Initiative is open. It updates immediately. Rename again; controls and history follow. Already-saved generic history also resolves the current name. | NOT TESTED |
| Optional naming | Disable Combat Log in a copied test world and refresh. Native/stored fallback names remain usable without errors or snapshot changes. | NOT TESTED |
| Tools/details | ZFT Tools and `game.zftRoundInitiative.open()` focus the embedded native tracker strip. Details opens the preserved compact/expanded window only on request; no duplicate normal-workflow pop-out. Open from a different viewed encounter and confirm its name/action target. | NOT TESTED |
| Initial rolling | Add PCs owned by connected players, two identically named NPC tokens, and an offline-owned actor. Request Initiative. Connected PCs become unrolled; GM rolls NPC/unowned using normal D&D5e formula. Each player rolls using existing controls. | NOT TESTED |
| Start protection | Use native Start Combat if still Round 0. Click Begin Round & Protect. Highest initiative is current; ties match tracker order. History contains the exact rolls. Another Begin/Request cannot overwrite them. | NOT TESTED |
| Mid-round accident | Advance THREE turns. Note current combatant and HP/effects. Use a native reset/reroll to spoil initiative. Restore Current Round. Original values return; selected combatant immediately before recovery remains selected where still present. Use its new Make Current row button if the accident already moved it. No round/HP rewinding. | NOT TESTED |
| Persistence | Refresh GM/player browsers after saving and after the accident. Restore still works from the saved round. | NOT TESTED |
| Next round | Foundry advances the round and preparation is announced automatically. Request new rolls and Begin. History shows independent Round 1/2 records, and Round 2 recovery uses only Round 2. Automatic preparation creates no snapshot. | NOT TESTED |
| Carousel | Open the installed Combat Carousel and native tracker together. Reroll/recover. Both show the updated records and selected combatant; no duplicate tracker or custom Carousel DOM controls. | NOT TESTED |
| Turn effects/Midi | Include representative start/end-turn effects and timers. Request, Begin and Restore; inspect automation and combat logs for duplicate/missing triggers. Record actual versions. Updating Combat.turn can activate third-party hooks. | NOT TESTED |
| Changes to participants | Remove a saved NPC and add a newcomer. Restore skips the removed ID, retains newcomer's current initiative, and distinguishes identically named NPCs. | NOT TESTED |
| Permissions | Player has no GM strip, row buttons or history. Non-active GM can view history but cannot mutate. Players cannot read private history journals. | NOT TESTED |
| Cancel/repeat | Cancel confirmation: no initiative change or snapshot. Rapid double click/repeated Prepare leaves rolls alone. Change initiative while a confirmation is open: action is refused as stale. | NOT TESTED |
| UI/notice | GM and player see short centered text for the viewed combat. Controls remain clickable through it. Existing Cinematics narration remains untouched. Check 1280/800px, zoom, long names, focus and reduced motion. | NOT TESTED |
| History retention | Close/delete a test encounter. GM history still lists its rounds. Disable/re-enable module: records remain. Do not delete the journal. | NOT TESTED |
| Missing roll | Leave one eligible combatant unrolled. Begin warns and lets the GM explicitly proceed; snapshot records it as unrolled, never as zero. | NOT TESTED |
| Rollback | Disable module and refresh clients. Existing tracker/Carousel and prior macros remain available. Private journal history is retained. | NOT TESTED |

Report PASS/FAIL with actions, exact versions, expected versus observed state and relevant `[ZFT]` messages. For failures, restore the prior dev.5 test package or disable the module. Snapshot records remain schema 1; no world or Cinematics/library data migration is needed.
