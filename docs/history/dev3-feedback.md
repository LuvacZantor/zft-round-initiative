# Owner feedback after dev.3

### Queued owner feedback after dev.3 delivery

Owner requests queuing an embedded Combat Tracker presentation, following the existing Turn Time control row, to avoid another separate Round Initiative pop-out competing for screen space.

- Proposed primary interface: a compact module-owned strip embedded in Foundry's existing Combat Tracker, with a brief current-round/protection status and icon controls for Request Initiative, Begin Round & Protect, Restore Current Round, and History. Preserve effect/disabled-reason tooltips and keyboard access. History and any full details open only on demand; normal actions should not require the independent floating control window.
- Support both the docked sidebar tracker and Foundry's own popped-out Encounter Tracker. This means embedding in the existing tracker, not creating or replacing a tracker or Carousel.
- Verified reference: `LuvacZantor/zft-turn-time` main commit `04e1fb692e5b7222b9de2a7580e1048c447a1b33`, `scripts/ui.js`, `injectModuleControls`. It inserts its OWN row as a sibling after `.combat-controls`, falls back inside `footer`, and otherwise appends to the root. It does not modify the native controls container or its parent because sidebar/popout layouts differ.
- Use the same safe placement pattern for a separate namespaced Round Initiative row near the timing controls. Never insert into or modify Turn Time's row/classes/state, and do not make Turn Time a required dependency. Preserve hook-order independence with or without Turn Time active.
- Resolve/bind the specific tracker window's viewed combat ID and validate it before every action; do not copy Turn Time's global `game.combat` lookup into a potentially different viewed encounter. Update enabled states, protection state and encounter-name tooltips after native updates and names changes.
- Keep injection idempotent on tracker re-renders/popout cycles. Refresh only the owned UI as needed and clean up its listeners/tooltips; no duplicate rows or polling-driven whole-tracker repaint. Review the current launcher, Tools entry and open API together so they focus/access the embedded controls instead of requiring a duplicate floating panel. Document any optional fallback deliberately.
- Required live checks: docked and popped-out tracker, both windows together, Turn Time enabled/disabled, narrow width/zoom, no duplicate rows, changing viewed combats, active-GM versus player visibility, disabled tooltips, and no impact on timing controls/Carousel. Keep all initiative, snapshot, automatic-notice and recovery semantics unchanged.

- Owner also requests that the AUTOMATIC round-change banners (for example, Round 3 Complete / Prepare for Round 4) stay visible longer. Current published default is 4 seconds through the shared `noticeDuration` setting. Queue an 8-second default for automatic transition notices with an adjustable duration. Keep the manual roll-request/begin notice duration at its existing preference; preserve already-customized settings and do not change rolling/round advancement. Ensure the longer preparation banner still yields immediately to a later manual Roll Initiative prompt, preserving the stale-notice ordering guards. The owner has been told the proposed automatic default is eight seconds; no new build has been delivered yet.

- Owner supplied the selected-token-to-current-turn macro and requests replacing that manual targeting step with a small per-combatant button inside this module's existing-tracker integration. Queue a GM-only `Make current combatant` icon beside each combatant's existing row controls, with a name-specific tooltip and accessible label. Clicking the row button directly selects that combatant; no canvas token selection or separate window is required. Include docked and popped-out trackers, and keep the row compact without displacing existing visibility, defeated, target, effects, initiative or Turn Time controls.
- Bind the action to the tracker combat ID and Combatant document ID, not actor name, actor ID, token selection or a cached turn index. Re-resolve the combatant's index from the current sorted `combat.turns` immediately before the write so repeated NPC names, resorting and multiple encounters cannot select the wrong entry. Apply the module's existing active-GM, busy/action and stale-view guards; disable or mark the current combatant's button and reject removed/stale entries without writing an invalid `-1` turn.
- This action performs only a native `combat.update({ turn: index })` when a change is needed. Keep initiative values/order, round number, protected snapshots and history intact. Let native combat updates notify the tracker, Carousel and timing integrations; do not call next/previous turn, advance the round, change world time, or directly manipulate another module. Verify native turn-hook/Midi-QOL and timer behavior in live Foundry rather than claiming the pointer update has no downstream effects.
- Next-build checks for this action: selecting a different entry mid-round, current-entry no-op, duplicate NPC names, reordered initiative, removed combatants, different viewed encounters, dock/popout together, GM/player permissions, rapid clicks, unchanged initiative/snapshots/round, and coexistence with Turn Time and Carousel. This is queued with the embedded toolbar and longer automatic notices, not yet delivered functionality.

This is queued design feedback, not implemented runtime. The delivered dev.3 ZIP remains unchanged until a new build is requested.
